# Atomic acceptance contract prototype

This is independent of `journal.ts` and is not connected to Engine. The earlier journal stages one aggregate value and fences uncertain publications for manual recovery. This prototype explores a different boundary: one adapter transaction covers MLS, app state, history, side-effect intents, and the replay ledger. After an uncertain commit or lost ACK, redelivery checks the ledger before staging again. A reused delivery ID with a different digest fails closed.

The test adapter only models atomicity in memory. It does not provide production durability, concurrency isolation, encryption, IndexedDB integration, lifecycle fencing, or cross-worker locking. A real adapter must provide serializable isolation, atomic rollback across every declared store, durable commit before transaction resolution, and a persistent, unbounded or safely managed ledger. It must reject a missing or uncovered store before any write. Its correctness cannot be verified by this interface. An adapter that lies about coverage or resolves early breaks the guarantee. Stage must be pure and use a private MLS clone; it must encode every relevant state change and durable side-effect intent in the covered stores. Compute the digest from exact envelope bytes using a collision-resistant hash, and bind delivery IDs to the correct account and session. The caller must prevent sign-out and competing transport races.

The effects value represents durable intents, not completion of remote effects. A separate dispatcher needs stable intent IDs and an explicit idempotency or reconciliation protocol. External network effects cannot generally be made exactly once by a local transaction. If an effect cannot be represented in the covered transaction, acceptance must fail without ACK. This prototype cannot discover such effects automatically. It does not integrate any existing Engine helpers, attachment stores, encrypted storage, or actual effect dispatcher. It must not be deployed as-is.
