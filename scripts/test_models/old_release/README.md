# Test-only old release model

This in-memory model is synthetic. It is not a real fence, journal, lock, filesystem, systemd unit, or deployment procedure. It does not touch production resources. Run `python3 -B -m unittest -v` in this directory.

The model requires an exclusive synthetic lock and two synthetic witnesses. It validates both operation-bound markers before it changes either marker. It journals `old_releasing` before it removes the update marker, then the systemd marker. It records `rolled_back` last. Missing markers are acceptable only when `old_releasing` is durable and their absence follows the release order. A `rolled_back` state requires both markers to be absent. An ambiguous fault stops the attempt until a simulated crash reloads durable state. Tests explore both durable outcomes for each fault. The event list is in-memory diagnostics only. It does not model durable evidence or prove live evidence preservation. Reconstruction requires a complete synthetic phase history and exact marker snapshot keys. Missing history, skipped transitions, and phase regression fail closed. Only an explicit trusted fresh-genesis fixture initializes new state. The retained synthetic history is a test fixture, not durable operational evidence. It does not model real storage.

Integration requires a separate design and real tests for lock ownership and concurrency; atomic journal writes and recovery; file and directory fsync semantics; marker identity and replacement races; real gate and process fencing; legacy data migration; failures across actual restarts; and evidence retention. The synthetic witnesses do not establish any of these properties. No integration or production safety claim follows from these tests.
